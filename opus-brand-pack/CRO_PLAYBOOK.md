# BETWEEN TWO SUNS — Evidence-led Ecommerce Conversion Playbook for Opus

This is not a list of gimmicks. Use it to protect conversion while pushing design quality.

## What current public evidence supports

### Performance is conversion infrastructure
- Dermalogica reported +45% conversion and +44% site-speed improvement after moving to Shopify.
- A later Dermalogica Horizon rollout reported +9% conversion, +12% faster page loads, +15% INP improvement, and CLS around 0.01.
- The Skin Nerd reported +19% conversion while average page-load time fell from ~9 seconds to under 2 seconds.
- Google's current "good" Core Web Vitals: LCP <=2.5s, INP <=200ms, CLS <=0.1 at the 75th percentile. For BTS target stricter internal budgets where practical.

Implication: award motion cannot block LCP, delay input, create layout shift, or make product discovery wait for a sequence.

### Routines / bundles can raise AOV and simplify choice
- NUXE reported +17% conversion and +€10 AOV after its Shopify transformation, specifically citing ready-to-use bundles / routines, strategic page optimization, service modules and checkout upsells.
- With only four BTS SKUs, the full routine can be a first-class purchasable object rather than an afterthought.

Implication:
- show individual total vs routine value clearly
- explain exactly what is inside
- one-tap add of all products
- AM/PM explains use, not a complicated configurator
- cart should identify genuinely missing routine steps

### Mobile PDP clarity is critical
Baymard's current mobile ecommerce research repeatedly identifies severe product-page usability issues and notes mobile ecommerce can convert substantially worse than desktop because of friction.

PDP first decision zone should contain, without hunting:
- product name
- role / primary benefit
- price
- size
- rating + review count when real
- skin type / suitability if material
- primary Add to Bag
- delivery / return reassurance
- payment reassurance where relevant
- gallery that immediately shows pack, texture, scale, and on-skin use

Do not hide core information behind conceptual scroll sequences.

### Product media should reduce uncertainty
For skincare, use the gallery to answer:
1. What is it?
2. How big is it?
3. What is the texture?
4. How does it apply / absorb?
5. How does it look on relevant skin tones?
6. Where does it fit in the routine?
7. What proof / actives matter?

Prioritize real photography / video over decorative CGI once production assets exist.

### Reviews and proof
- Put rating + count near the buying decision when enough verified reviews exist.
- Never invent review counts.
- For a new brand with few reviews, do not foreground "0 reviews"; use clearly labelled tester-panel / clinical / consumer-study evidence if real.
- Reviews become more useful when filterable / contextualized by skin type, concern and possibly location.
- Proof hierarchy: claim -> substantiation -> who it is for -> how to use -> reviews / outcomes.

### Delivery and returns
Baymard research supports showing shipping / return information on the PDP, not only at checkout.
Where possible, communicate an estimated delivery DATE or date range rather than only "1–3 day shipping."

Egypt / GCC:
- show COD availability and any fee before checkout
- expose local payment methods without clutter
- show returns / exchange rules clearly
- localize delivery promises by market

### Checkout
Baymard:
- checkout should be linear, predictable and low-friction
- guest checkout should be prominent
- do not make users create an account to buy
- costs should not appear as surprises
- distinguish order review vs order confirmation clearly
- avoid unnecessary fields

BTS:
- keep Shopify checkout conventional and fast
- express payments where supported
- COD clearly visible
- no creative scroll-jacking or experimental transitions in checkout
- treat checkout experiments separately from brand-site releases

### Cart drawer
On add:
- open quickly
- show exact item(s), quantity, total
- show routine savings if triggered
- show free-shipping / delivery status
- show estimated delivery
- show COD / relevant payment reassurance
- clear Checkout CTA
- allow edits / remove without leaving drawer

### Cross-sell / complete-the-routine
Baymard finds irrelevant cart cross-sells quickly erode confidence and can feel aggressive. Cross-sells should be clearly relevant and contextual.

For BTS, because there are exactly four complementary steps:
- "Complete your routine" is legitimate if a missing step truly complements the cart
- label why it is suggested (e.g. "Step 03 — after Clarity")
- never insert an interstitial that must be accepted/rejected before checkout
- stop recommending once the full routine is present

### Shipping threshold
A free-delivery threshold can increase basket size if it is:
- transparent
- achievable
- shown in cart / drawer
- not manipulative
- aligned with margin economics

If the threshold sits just above a typical two-item basket, a relevant third step may become a natural AOV nudge. Validate with real economics before finalizing.

### Routine pricing / savings
If routine discount is used:
- show individual total
- show routine total
- show absolute money saved and/or % saved
- apply automatically when the qualifying set is in cart if technically feasible
- never use fake crossed-out prices

### Quick add
Homepage / product shelf should enable:
- one tap to add a single SKU
- one tap to add the complete routine
- optional quick detail without forcing PDP
- full PDP remains available for deeper evaluation

### Sticky CTA
On long mobile PDPs, a sticky Add to Bag can reduce the cost of returning to the purchase action, but:
- it must not cover content
- it must preserve thumb reach
- it should hide / reconfigure when keyboard or other critical UI is active
- it must not duplicate multiple competing CTAs

### Personal service
NUXE references service modules and a virtual skincare assistant; PAUL & JOE has publicly reported strong conversion among users engaging with live beauty consultation. For Egypt/GCC, WhatsApp can be a more natural service channel than an on-site bot.

Use service for:
- routine questions
- skin-type questions
- order reassurance
- product layering
Not as a modal that blocks browsing.

### First-order capture
Email / WhatsApp/SMS acquisition can be valuable, but:
- do not fire an immediate full-screen popup before the user understands the brand
- consider delayed / exit-intent or post-engagement capture
- offer real value (e.g. early access, useful skincare guidance, launch benefit) rather than spammy urgency
- test incentive economics; do not train the brand to require discounts

### Subscription / replenishment
Do not force subscription at launch.
Introduce once:
- replenishment intervals are known
- repeat behavior is measured
- operational reliability is strong

When introduced:
- show one-time vs subscribe clearly
- make cancellation / pause easy
- do not preselect subscription deceptively

### Search / navigation
With four launch SKUs:
- no complex mega menu
- no collection-filter theater
- direct access to all four products and routine
- clear Help / About / Delivery / Contact / Arabic
- on mobile, do not hide every important route behind an ambiguous hamburger if there is room for Shop / Routine / Bag

### Trust
For a new skincare brand, trust needs to sit close to buying:
- verified reviews / tester proof when real
- ingredient transparency
- dermatologist testing only if legitimately substantiated
- authentication / official-store reassurance if relevant
- clear contact / WhatsApp
- delivery and return policy
- payment / COD methods
- regulatory / SPF claims only where approved
- never use fabricated badges

### Localization
Egypt:
- EGP
- COD
- card / wallet / local-payment support
- Arabic / English
- Cairo / Alexandria / governorate delivery clarity where relevant

UAE:
- AED
- Arabic / English
- VAT-inclusive pricing as required
- Apple Pay / cards / local BNPL if commercially appropriate
- local delivery promises

Saudi Arabia:
- SAR
- Arabic / English
- Mada / Apple Pay / relevant BNPL if commercially appropriate
- local delivery promises / regulatory content
- art direct Arabic, do not simply mirror English

### Performance budgets for design development
External Google "good" thresholds:
- LCP <= 2.5s
- INP <= 200ms
- CLS <= 0.1
Internal BTS aspiration:
- LCP <= 2.0s on representative mobile where achievable
- INP <= 150–200ms
- CLS <= 0.05

Practical design rules:
- hero must paint without waiting for JS
- no mandatory preloader
- no autoplay heavy video as LCP
- lazy-load below-fold media
- use responsive AVIF/WebP
- avoid large WebGL scene unless it materially improves the concept AND passes device testing
- respect reduced motion and Save-Data
- every animation needs a commercial or brand reason
- do not stack animation libraries and third-party scripts casually

## What high conversion does NOT mean
Do not:
- cover the page in badges
- add countdown timers
- use fake scarcity
- use dark patterns
- force bundles
- hide singles
- block checkout with upsells
- make the site look promotional / discount-led
- replace brand desire with CRO widgets

The best version integrates the conversion mechanics into the art direction.

## Public evidence / sources supplied to Opus
- Shopify — Dermalogica: +45% conversion, +44% speed after Shopify migration
- Shopify — Dermalogica Horizon (2025): +9% conversion, 12% faster loads, 15% better INP
- Shopify — NUXE: +17% conversion, +€10 AOV; routines / bundles / service modules
- Shopify — The Skin Nerd: +19% conversion; page load from ~9s to <2s
- Shopify — Omy Laboratoires: +35% repeat business after redesign / personalization work
- Shopify — Wild Cosmetics: public case study reports 8% conversion and 40–50% subscription participation in its category; use as evidence of simplicity / checkout / retention, NOT as a universal benchmark
- Baymard — Product Page UX / Mobile Ecommerce UX / Checkout UX / Cross-sells research
- Google Search Central / web.dev — Core Web Vitals thresholds

Important: do not claim a tactic is the "highest converting in the world" when public evidence does not support that. Treat these as the strongest evidence-backed patterns and continuously A/B test against BTS's own customers after launch.
